Label-free step-error localization on PRMBench

For the advisor meeting on Thursday 2026-10-15. This page shows PRMBench results first. ProcessBench is context only. The task: find the wrong steps in a given answer, with no labels and no training. Qwen3-8B reads each answer in one teacher-forced pass. We compute token-probability channels for each step. Then we fuse the channels without labels.

All numbers are from the corrected input. The earlier version of this page used a teacher-forcing input without the empty think block. We fixed the input, masked the first forced token, and re-scored everything. The fix made our numbers slightly lower: the bug inflated the earlier results by about 0.01 AUC. Details. The supervised LR reference is re-scored too. The external benchmarks are not re-scored yet.

What changed: the think-block fix

Qwen3 in /no_think mode writes an empty think block (<think></think>) before the answer. Our teacher-forcing input did not have this block. Thus the model saw the answer steps in an unexpected place, and the surprise channels were wrong on the first tokens. We re-generated the PRMBench and ProcessBench telemetry with the block. We also removed the first forced token of each answer from the channels, because Qwen3 expects a fixed opening word there.

Then we re-ran the frozen scorers on the new input with no other change. A replay on the old input gives the old numbers again (max difference 3.3e-4), so the chain is correct.

The change is small and mostly negative: {{+d_lo}} to {{+d_hi}} per bank and method, mean {{+d_all}}. Thus the bug slightly inflated the numbers that we showed before. The order of the banks and methods stays almost the same.

Setup

PRMBench: 6,969 answers, 94,203 steps. An LLM inserted the errors. Scoring model: Qwen3-8B. Each method fits on one cell (one benchmark subset × one scoring model). Only the LR reference uses labels.

Feature banks. A bank is a set of step channels. Nested banks: N11 ⊂ N13 ⊂ N22 ⊂ N40 ⊂ N53. Each has a "digit twin" with digit channels added: N14, N16, N25, N43, N56. N16 is the leading bank. We chose N16 after we saw the results.

Methods (all see the same z-scored channels of one bank)
NameWhat it does
Plain averageMean of all channels. No filter. No sign flip.
DS-filter averageDawid–Skene finds the channels that point the wrong way. Remove them. Then average the rest.
Continuous L-SMLFind groups of dependent channels. Fuse each group by its leading eigenvector. Then fuse the groups (Jaffe et al. 2016).
IU-PCREstimate the covariance of each channel with the hidden error. Weight by 2 principal components (Dror et al. 2017; Tenzer et al. 2022).
Tail-vote pipeline (4 variants)Each channel votes "error" on its top 20% of steps. Dawid–Skene drops wrong-way channels. L-SML groups the channels. Inside a group: MEAN, HEM or TCI. Between groups: MoM weights. _cc = vote per channel, quota per cell. _ga = vote per group, quota per answer.
LR (reference)Logistic regression on the same channels. It uses step labels. Source-group cross-fit. It shows the headroom. It is not a competitor.

PRMBench · official PRMScore

The official PRMScore needs a yes/no decision for each step. Our methods give a score, not a decision. Thus we need a flag rule. All rules below are label-free: each threshold is a quantile over all scored steps.

Flag rules
RuleWhat it flags
R0A step whose method score (z-scored inside its answer) is in the top 20% of all steps. Because the score is relative to the answer, about 20% of the steps of every answer get a flag.
R1A step whose global score is in the top 20%. Global score = equal mean of the DS-surviving channels, each z-scored once over all steps (not inside the answer). Thus some answers get many flags and some get none. R1 does not depend on the fusion method.
R2The number of flags per answer comes from R1. The method score picks which steps get them.
TOP1, TOP2Exactly 1 or 2 flags per answer. TOP2 is a control, not a method: PRMBench inserts about 2 errors per answer, so TOP2 uses knowledge of how the benchmark was built.
{{T_OFF}}

R0 on N16 gives {{r0_lo}} to {{r0_hi}}, about equal to PRM-7B ({{prm_off}}). R1 gives {{r1}}. R2 ({{r2_ga}} for MEAN_MOM_ga) gives no gain over R0. TOP2 gives {{top2_lo}} to {{top2_hi}}, but it uses the benchmark's construction, so it is only a reference.

{{T_FLAG}}

R0 flags at least one step in {{%r0_ctrl}} of the error-free control answers. R1 reduces this to {{%r1_ctrl}}, because it compares steps across answers. This is the main difference between the rules. The pooled PRMScore does not show it, because controls are not in the pooled score.

Caveats

  • All PRMBench numbers are development data. We chose N16 after we saw the results.
  • The official PRMScore uses the PRMBench evaluator port in the repository. Two adaptations: we have no redundancy head, so redundency and circular use the validity fallback; multi_solutions has no error steps, so it is not in the Sensitivity mean.
  • R1 uses a global score that we re-built from its written definition. The original R1 inputs are gone, so R1 and R2 are not a replay of the earlier decision-rule study.
  • The Mind the Gap reference is not on this page. Its input file is gone, so we could not re-score it.
  • The external benchmarks are not re-scored yet.
  • "LR minus best" uses the best pipeline variant after we saw the scores. Thus each gap is a lower bound.
