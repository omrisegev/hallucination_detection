How to read this

What matters is the method that does not use a fixed subset. GOOD_5, GOOD_6 and LOCO_5 were chosen by hand using answer keys, so they are the bar rather than competitors — they carry the reference_macro role and picks own subset = no — fixed. Use the role filter to drop them.

Best method that is not a fixed hand-picked subset: upcr.rho_polarities = 0.7551. GOOD_6 = 0.7594. The gap of 0.43pp is the open problem.

Every description is quoted from spectral_utils/glossary.py (family note + variant note), the repo's single source of truth with a coverage gate — this page writes no prose of its own about any method. Similar methods are derived structurally: same base variant with a different size/K suffix first, then other members of the same family.

Feature counts are computed on the 25 in-scope cells only, so they describe the same rows as the AUROC column — the bench CSVs also contain out-of-scope cells. The same method under a different pool mode is a separate row, because its chosen size genuinely differs (a2.dufs picks 19.0 features under c46 and 10.8 under h16). U-PCR rows use every view; their count (~11.7 of ~29) is what survives U-PCR's own label-free exclusion step, which is pruning, not subset selection.

Provenance — how far to trust each number

Every row was replayed through today's fusion code on the same 25 in-scope cells (scripts/upcr_study/reproduction_audit.py): 63 reproduce to the last decimal, 49 differ by less than their own numerical noise (both values are draws from the same distribution — see below), 44 differ for a named reason (the Step-189 K-override clamp, the Step-205 exact small-m solve, or an h16 row whose published number came from the Step-153 lookup table rather than a live fusion), 4 are not replayable (a2's two clustering-swap arms store their group assignment nowhere, so replaying them would be a different method, not a check), and 0 are unexplained. Sort by reproduces today? to see it.

One defect, and it was structural. The Eq.15 score matrix, which decides how features are grouped, has no valid term at three features (it is identically zero, so the grouping is pure tie-break) and exactly two at four. At four features that is enough to make the answer depend on rounding rather than on the data: on one real cell, computing the covariance from a non-contiguous column slice instead of a contiguous copy of the same numbers changes it by 5.5e-17 — BLAS summation order alone — and that moves the K=3 partition, which moves the Eq.14 residual 0.60 → 0.39, which flips the selected K, which moves AUROC by 9.7pp.

It is now solved rather than patched. Spectral clustering is only a heuristic for “the partition minimising the Eq.14 residual”, and at small m the heuristic ties. So at m ≤ 4 we no longer approximate: every partition is enumerated (5 of them at m=3, 15 at m=4) and the exact minimum taken, with a deterministic tie-break. The covariance input is pinned to a canonical memory layout at every m, and a near-degeneracy flag now fires whenever the winning grouping beats its nearest rival by less than float noise — so a coin flip is visible as one instead of being reported as a measurement. This bought determinacy, not accuracy (+0.03pp, 15W/10L, p=0.70 on the rows it touches), and every headline row is unchanged to 0.00pp. Rows whose numbers moved because of it are labelled code fix: Step-205 exact small-m solve below. A standing regression gate (U5 in scripts/verify_residual_scaling.py) now asserts the grouping is invariant to memory layout, feature order, and a 1e-12 jitter.

So the table reports numerical determinacy as a column. stability_audit.py re-fuses every row's stored subsets with the feature matrix jittered by a relative 1e-10 — eight orders of magnitude below any real measurement precision — across 5 seeds. 0 of 164 measured rows move their macro by at least 0.5pp under that jitter and are flagged NUMERICALLY UNDETERMINED: their leaderboard position is not meaningful at the resolution the table prints. This is a property of L-SML on small subsets, not of any one implementation — reverting the vectorisation would only re-pick one arbitrary side of the tie.

Read every size-3 row with that in mind. Zero is the honest value, but it also means L-SML has no structural information at all at three features — the group assignment is whatever the clustering's tie-break yields. 17 rows sit at three features on at least half their cells (a4.anchor_adapt, a3.cae_k3, a1.upcrres_greedy, a1.upcrres_greedy+scale_complete, a1.minres+K_ah+scale_complete, a1.relres_greedy+scale_complete …). Those are not measurements of the fusion model; they are measurements of a degenerate case of it.

Loading scale. Published numbers are all at unit, L-SML's historical rank-one loading estimator, which Step 204 Phase 0 showed does not satisfy the paper's Lemma 1. The two right-hand columns give the identical subsets re-fused at eigen and complete, so the sensitivity is visible per row rather than asserted globally. Only a1_residual selects using L-SML, so it is the only family where the scale can change which features are chosen — hence the separate +scale_complete rows. Every other family's objective is scale-free and its published subsets stand as selected.
