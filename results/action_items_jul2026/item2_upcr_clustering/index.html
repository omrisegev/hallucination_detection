Item 2 — a clustering mechanism inside U-PCR

Already built and refuted in Step 204. This page is the evidence, so the decision does not have to be taken on trust.

Verdict: built, tested, refuted — and its premise was a confound. The code is still in the tree at spectral_utils/upcr_clustered.py.

What was built

U-PCR assumes the views' errors are uncorrelated. The relaxation is to assume that only across L-SML clusters, and to fit the additive system on cross-cluster pairs only — which is exactly the “add clustering to U-PCR” idea. An identifiability requirement was derived and enforced: the cross-cluster pair graph is complete multipartite, so K ≥ 3 is required; at K = 2 it is bipartite and the parameter is unidentifiable.

What happened

TestResult
Both pre-registered gatesFAILED
AUROC against the unclustered arm−4.46pp, 9W/16L, p = 0.030
Premise: same-cluster vs cross-cluster fit errorraw ratio 2.03×
… the same ratio matched on |Cij| decile0.97–1.00× — the gap disappears
… a random partition instead of the clustersreproduces the raw gap

So the apparent same-vs-cross structure was pair correlation wearing a cluster label (fit error tracks |Cij| at Spearman 0.870). Once you control for correlation magnitude there is no clustering effect left to exploit.

The one variant never run, and why it is rated low

K-means on the two-component eigenvector coordinates (v₁[i], v₂[i]) would recover hard groups from the U-PCR fit rather than importing L-SML's. It has not been tried. Two measurements make it unpromising:

  • One-component U-PCR is exactly PC1 of the surviving views (cosine deviation 7e-12), so the whole ρ / g² apparatus enters only through the exclusion mask.
  • The second component is inert on our data: sweeping lambda2_threshold from 0.05 to 0.25 changes the component count on 24 of 25 cells and buys +0.43pp (9W/15L, p = 0.16).

There is nothing for the second component to cluster on.
