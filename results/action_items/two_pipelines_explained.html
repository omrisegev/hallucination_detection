The one-paragraph version

Both arms share the same skeleton and differ in one middle block. Both end with a single hand-set bit. The interesting finding is not that either selector wins — neither does — but which part of each pipeline is load-bearing. We ablated every component. Selection contributes almost nothing in either arm, and so does the weight estimate. What carries the number is label-free orientation and a dependency-aware fusion over a moderately-sized pool. That is why eight algorithm families all converged to roughly the same 75%.

Two traps in that listing

V arrives already hand-oriented. Line 383 applies ALL_SIGNS, so both U-PCR call sites multiply by hand first to recover the raw view before deriving polarity themselves. This works because zscore(raw·s) == s·zscore(raw) for s = ±1. Getting it backwards silently scores the incumbent arm instead of the new one; both files carry a warning comment.

Two different objects are called "rho". See the box below — this one is not the one in the arm's name.

Name collision, worth killing on sight. cell.rho is a p×p |Spearman| matrix between features — observable, and read by neither of these two arms. U-PCR's rho_hat is a length-m vector, rho_i = Cov(f_i, Y) — each view against the unobservable target. "U-PCR + sign(rho)" means the second one. Everywhere below, "rho-hat" is the vector and "the Spearman matrix" is the matrix.

The central mechanism

2. How rho_i = Cov(f_i, Y) is estimated without ever seeing Y

This looks circular and is not. It is Theorem 1 of Dror, Nadler, Bilal & Kluger (arXiv:1703.02965). U-PCR never uses Y. It uses the footprint Y leaves on the covariance between views — and that footprint is observable. rho is not measured, it is solved for, from a linear system whose coefficients are ordinary view-view covariances.

The model (§4.1)

Let g(x) = E[Y|X=x] be the best predictor anyone could build. Write each view as f_i(x) = g(x) + h_i(x). Define g2 = E[g²] = E[g·Y] (the shared signal) and a_i = E[h_i·Y] = E[h_i·g]. Then immediately:

rho_i = E[g Y] + E[h_i Y] = g2 + a_i                              (Eq. 11)

and the single assumption — the regression analogue of Dawid–Skene:

E[h_i(X) h_j(X)] = 0   for i != j        "uncorrelated deviations"   (Eq. 13)

Now compute the observable covariance between two different views:

C_ij = E[f_i f_j] = E[(g + h_i)(g + h_j)]
     = E[g^2] + E[h_i g] + E[g h_j] + E[h_i h_j]
     =   g2   +    a_i   +    a_j   +     0            <-- Eq. 13 kills the last term

C_ij = g2 + a_i + a_j                                                    (Eq. 14)

The left side is computable from the data matrix alone. So each pair of views gives one linear equation in the unknowns. With m views that is m(m−1)/2 equations for m unknowns — over-determined at m ≥ 3, which is exactly where upcr_fit raises "U-PCR needs m >= 3 (Assumption A4)".

The whole method is matrix completion. Treat the optimal predictor g as an (m+1)-th view we never observe. In the full (m+1)×(m+1) covariance of (f_1 … f_m, g), the missing last column IS rho (since Cov(f_i, g) = rho_i) and the missing corner IS g2 = Var(g). Assumption (13) forces C_ij = rho_i + rho_j − g2, so the observed block determines the missing column up to one scalar — and Eq. 20 supplies that scalar.

The identity that makes it concrete (m = 3)

C_12 = g2 + a_1 + a_2
C_13 = g2 + a_1 + a_3          add the first two, subtract the third:
C_23 = g2 + a_2 + a_3          C_12 + C_13 - C_23 = 2 a_1 + g2

              C_12 + C_13 - C_23 + g2
    rho_1  =  -----------------------
                        2

Three view-view correlations and one scalar, and you have view 1's covariance with the unobservable target. Verified on data generated from the model: the closed form gives 0.24666 against a true 0.25000. For m > 3 it is the same system solved by least squares over all pairs — additive_design + solve_additive, each design row being e_i + e_j.

Relative polarity lives in the covariance structure; the global sign provably does not. Measured on all 25 in-scope cells, max|Δrho| under a global flip is exactly 0.000e+00. That single contrast explains both why per-view polarity is free and why the anchor bit is not.

Honest caveat: flipping a view breaks assumption (13) for that view (E[h'_i h_j] = −2a_j ≠ 0), which is why the other entries drift slightly above rather than staying pinned.

Why the pair equations cannot see g2, and what Eq. 20 does about it

Every design row sums to 2, so shifting all of rho by q/2 shifts every fitted C_ij by exactly q (Eq. 16). The residual is therefore flat in q — verified bit-identical at q = 0, 0.6 and 5.0 (9.964335e-03 every time). That is why the code solves the system once and slides it, and why g2 needs its own criterion.

Var(Y) is assumed known. g2 is not. They are different quantities. Algorithm 1's input line reads "Predictions f_i(x_j), E[Y] and Var(Y)", and §4.2 says explicitly that g2 "would seldom be known to the practitioner". g2 = E[g(X)²] is the variance of the optimal predictor; Var(Y) − g2 is the irreducible error. Var(Y) does exactly one job: it sets the upper end of the g2 search interval. For us g2/Var(Y) reads as "how much of correctness is knowable from the trace at all" — the paper's difficulty index, and the basis of its STOP rule, which we run off.

What A1 costs us. Moment-matching the z-scored rows to Y's moments multiplies every row by the same constant, and a positive constant leaves eigenvectors fixed while rho and lambda cancel in Eq. 21 — so the model's accuracy rate p drops out entirely and never needs to be known. What does not cancel is the ratio var_y / mean(diag C). In the paper A1 pins it; for us it is a free parameter, set empirically to 0.25. So: A1 is free about p, and not free about scale.

Why v1 alone in Eq. 20, but v1 and v2 in Eq. 21?

§4.3 scopes the two-component rule explicitly: "… Then, Eq. (21) is replaced by …". Eq. 20 is written with v1 alone and stays that way. Conceptually the two steps do different jobs:

StepJobWhich subspace, and why
Eq. 20model selection — pick the nuisance parameter qv1 alone. Lemma 2 gives the O(ε) prediction that rho lies along v1; the departure from the v1 line IS the criterion's signal.
Eq. 21estimation — build the weight vectorv1 and v2. To O(ε²) the paper shows rho lies in span{v1, v2}, so discarding the v2 part loses real signal when lambda2 is non-negligible.

A seam worth volunteering before it is found: Eq. 20 chooses q by minimising the very off-v1 component that Eq. 21 then uses. Not incoherent — a nuisance parameter fixed under one approximation, a quantity estimated under a finer one — but it is an unresolved asymmetry in the paper, not something we introduced. Measured, it barely matters: k=1 0.7551 vs k=2 0.7541 (−0.09pp, 2W/3L, p=0.345), and only 5 of 25 cells differ at all — because when the argmin sits on the grid boundary, the shape of the curve is irrelevant.

Shared fusion

4. The L-SML core

This is arm 2's fusion and also GOOD_6's, so it is the piece the reference bar and the DUFS arm share. Paper: Jaffe, Fetaya, Nadler, Jiang & Kluger, Unsupervised Ensemble Learning with Dependent Classifiers (arXiv:1510.05830).

The problem it exists to solve. Plain SML assumes conditionally independent errors. Our 30 views violate that about as badly as possible — they are all deterministic functions of the same token-level trace. L-SML's answer is not to assume independence but to discover the dependence structure and quotient it out.

Lemma 1 — the structure that makes it possible

              /  v_off_i * v_off_j     if c(i) != c(j)     <- different groups
    r_ij  =  <
              \  v_on_i  * v_on_j      if c(i) == c(j)     <- same group      (Eq. 10)

The covariance is two rank-one matrices stitched together by the grouping. If you knew the assignment c, you would know exactly what shape R should have. Everything downstream is: find the c that makes R look most like this.

INPUT   views (m arrays, z-scored, sign-oriented);  anchor

 1  R <- cov(X^T)                              # layout pinned contiguous (see note)
 2  S <- score_matrix(R)                       # Eq. 15 dependency detector
 3  for K in 2 .. min(m-1, 8):
        c_K   <- spectral_cluster(S, K)
        Delta_K <- residual(R, c_K)            # Eq. 14 reconstruction error
    K*, c <- argmin over K
    (at m <= 4: skip the above, enumerate ALL set partitions exactly)
 4  for each group g:  xi_g <- sml_fuse_signed(views in g)      # WITHIN-group
 5  fused <- sml_fuse_signed(xi_1 ... xi_K)                     # ACROSS groups
 6  fused <- anchor_orient(fused, anchor)

Step 4 collapses each dependent group into a single virtual classifier. By construction those K virtual classifiers are conditionally independent, so step 5 is legitimately plain SML. The dependence is not modelled away — it is absorbed into the group summaries.

What the Eq. 14 residual is actually measuring

Delta(v_on, v_off, c) = SUM_{i != j}     1_c(i,j) * (v_on_i  v_on_j  - r_ij)^2
                                    + (1 - 1_c(i,j)) * (v_off_i v_off_j - r_ij)^2     (Eq. 14)

For every off-diagonal pair the grouping makes a prediction about what r_ij should be, and Delta is the sum of squared prediction errors. In code it is three lines: build a two-rank-one mosaic (pred = where(same_group, outer(v_on,v_on), outer(v_off,v_off))), subtract R, square, zero the diagonal, sum. Four things about it that are easy to get wrong:

  • v_on and v_off are fitted, not given. Delta_K is a profiled residual — the best the model can do under that grouping.
  • Masked entries are free parameters, not zeros. Lemma 1 says nothing about i = j, nor about within-group entries when fitting v_off.
  • The parameter count is 2m regardless of K, so no complexity penalty is needed — raising K only reassigns which entries each rank-one pattern explains.
  • K = 1 and K = m both collapse to a single rank-one model of R. Only intermediate K gets two patterns plus a partition, which is strictly more expressive. The code caps K at m−1 to exclude the all-singleton end. (Honest wrinkle: at the extremes one vector goes unconstrained, so mid-range K has slightly more effective freedom — the criterion is not perfectly flat across K.)

And we are not minimising Eq. 14. Lemma 3 says that is NP-hard. Spectral clustering on the Eq. 15 score matrix generates one candidate per K, and Delta is used only to rank those few candidates.

Two numerical landmines, both already stepped on

  • At m = 3, Eq. 15 carries no information at all. The double sum is literally empty. The vectorised form computed it as a difference of large partial sums and left ~1e-17 of cancellation noise, which flipped a real grouping from [0,0,1] to [1,0,1], moved the residual 0.00297 → 0.05284 and the AUROC 0.6023 → 0.5891. Treat any size-3 fusion as structurally undetermined.
  • At m = 4 a 5.55e-17 difference in R — BLAS summation order alone — flipped the chosen partition and moved AUROC by 9.7pp. Hence the exact enumeration of all set partitions at m ≤ 4 (Bell(4) = 15), and the pinned memory layout at step 1.

A concrete research lead. Full pool with oracle K scores 0.7573, against GOOD_6's 0.7594 — essentially a tie. So on the full 30-view pool the gap to the hand-picked subset is largely a K-selection problem, not a pool problem, and a better K rule is worth up to 1.17pp. Oracle K is label-peeking, so this is a ceiling, not a result.

One property worth carrying: L-SML is exactly invariant to input feature signs (Step 201, 1150/1150 sign vectors, bit-identical output). That is why the 42 hand polarities were already free on this arm, and why sign(rho) — worth +1.46pp on U-PCR — buys nothing here. The only orientation prior on arm 2 is the single anchor bit at the end.

Arm 2

5. DUFS parameter-free + L-SML

A two-stage pipeline with a clean seam: DUFS picks a subset from the unlabeled V, then the same L-SML above fuses whatever it picked. Nothing is co-designed, so the only thing changing versus GOOD_6 is the selection step.

The idea in one paragraph. Give every feature a gate z_i ∈ [0,1], multiply the data by the gates, and build a similarity graph over samples using only the gated data. Then ask: under which gate settings does the data look most structured on its own graph? Features whose gates can close without destroying that structure are uninformative. The self-reference is the point — the graph is rebuilt from the gated features at every step.

INPUT   V (n x p) z-scored, sign-oriented;  anchor;  rng

 -- stage 1: DUFS parameter-free gates ------------------------------
 1  X <- subsample rows of V to at most R_MAX = 1200
 2  for each of 5 seeds:
        mu <- 0.5 * ones(p)                        # gate means, the ONLY parameters
        for 120 epochs:
            B  <- random minibatch of 256 rows
            z  <- clip(mu + N(0, 0.5^2), 0, 1)     # stochastic-gate reparameterisation
            Xt <- B * z                            # gated batch
            W  <- self_tuning_affinity(Xt, k=7)    # graph over SAMPLES, built from Xt
            P  <- (D^-1 W)^2                       # 2-step random walk
            tr <- -trace(Xt^T P Xt) / |B|
            Pz <- 0.5 * (1 + erf(mu / (0.5*sqrt2)))   # P(gate i is open)
            loss <- tr / (sum(Pz) + 1e-8)          # <-- Eq. 7.  NO lambda.
            Adam(lr = 2e-2).step()
 3  mu_bar <- mean of the 5 seeds' mu              # determinism
 4  cols <- { i : mu_bar_i > 0 }                   # the STG readout rule
    if |cols| < 3: fall back to the full pool

 -- stage 2: fusion, unchanged --------------------------------------
 5  fused <- lsml_continuous(V[:, cols])
 6  score <- anchor_orient(fused, anchor)
Notation trap. DUFS's L_rw is D⁻¹K, the random-walk transition matrix — not the Laplacian I − D⁻¹K. Reading that "L" as a Laplacian gets the sign backwards. Minimising −trace(Xtᵀ P² Xt) maximises agreement between diffusion neighbours.

Eq. 6 → Eq. 7: how the last hyperparameter disappears

if param_free:  loss = trace / (Pz.sum() + PF_DELTA)     # Eq. 7   <- a2.dufs_pf
else:           loss = trace / d + lam2 * Pz.mean()     # Eq. 6   <- a2.dufs

Eq. 6 is the usual additive trade-off: fit plus lambda × sparsity, and you have to choose lambda. Eq. 7 makes it a ratio: since trace is negative, dividing by the number of open gates makes the objective structure per open gate. Opening a gate must pay for itself, the trade-off becomes scale-free, and lambda vanishes. This is the paper's own device, used for all its two-moons experiments.

This is a selling point, not just convenience. The DUFS paper itself picks lambda by sweeping it and keeping the run with the best clustering accuracy — which is computed against labels. The paper's own protocol peeks. Eq. 7 removes the parameter entirely, so a2.dufs_pf is not merely cheaper (5 trainings instead of 20) — it is the variant that makes this arm honestly label-free, and it is more faithful to the paper than our lambda rule, not less.

The finding

7. What actually carries the result

Every component of both arms was ablated on the same 25 cells. The pattern is consistent and it is the most useful thing on this page.

This corrects a claim in the July advisor email. The email said "its weighting turned out to be the part that does not matter … what it really decides is which features get dropped." The first half is confirmed and is in fact stronger than stated. The second half does not hold up — removing the exclusion step costs 0.06pp at p=0.979. Selection is not carrying the result either.

This explains why every direction landed at roughly 75%. Neither arm's selection and neither arm's weighting is load-bearing. What carries the number is (a) label-free orientation and (b) a dependency-aware fusion over a moderately-sized pool. Once you have both, the specific subset is close to interchangeable — so of course eight algorithm families converge to the same place. That reframes the result from "I tried many things and none won" to "I measured why nothing wins, and selection is not the bottleneck here."

One mechanism worth having ready: exclusion and v1-weighting are substitutes. With uniform weights, exclusion is worth +1.40pp (0.7469 vs 0.7329); with v1-shaped weights it is worth nothing, because the leading eigenvector already down-weights weak views smoothly. You need one of the two, not both.

A deviation that is in neither list, upstream of both arms

z-scoring is itself a per-feature rescale. The pipeline is exactly invariant to a global rescale (verified: multiply every view by 7.3 and max|ΔAUROC| = 0.00e+00) but not to a per-feature one — sᵢsⱼ(g2+aᵢ+aⱼ) is not of the form g2'+aᵢ'+aⱼ', so Eq. 14's additive structure breaks. We therefore impose the model on the correlation matrix, not the covariance matrix. Justification: the paper's regressors all predict Y in Y's units; our 30 views are entropies in nats, log-partition energies, spectral band powers and token counts, with no common scale. Some normalisation is mandatory.

Anticipated questions

9. The questions this work invites, with answers

You call it label-free, but there is still an anchor. How free is it really?
One bit, and it is provably not removable from this estimator. rho-hat is a function of C alone, and C(−F) == C(F) because a global flip flips both indices in every product — measured max|Δrho| under a global flip is exactly 0.000e+00 on all 25 cells. When we did derive the global sign structurally (g2 ≥ 0 so rho should lean positive), it was wrong in 25 of 25 cells and the macro fell to 0.2449. That variant now raises rather than existing silently. Everything else — all 30 per-view polarities, the subset, the pool size — is derived.
sign(rho) agrees with your hand signs only 56%. That is chance. So what is it recovering?
The right reference. Against the label-derived polarity it agrees 91.6% (p<1e-4). A whole-pool audit found 15 of 30 hand signs have mean oriented AUROC below 0.5. The estimator disagrees with us and agrees with the truth; the hand prior was the outlier.
Is this the paper's algorithm, or yours?
Algorithm 1's structure is faithful: additive pair equations, the Eq. 16 analytic shift, Eq. 20 g2 selection, exclusion, refit, Eq. 21 weights with the λ2 rule. Seven deviations are documented and each is exposed as a flag so the A/B is measurable rather than arguable. Running fully paper-faithful scores 69.1% against 73.9% for the path we kept, so we kept it and say so. The one deliberate addition is orientation, which the paper never faces because its regressors are all trained to predict Y and are positively oriented by construction.
Your g2 is pinned at the grid ceiling on most cells. Is the model-selection step doing anything?
Yes, and the pinning is a clipping artefact worth 0.12pp. With scale_ratio = 0.25 the grid is [0, 0.25] against a unit diagonal, and the argmin lands on the boundary on 21/25 cells. Widen it to the paper's calibration and it un-pins completely (0/25) and settles at g2 ≈ 0.44 — and doubling the grid again moves that by 0.003, so the criterion has a stable interior argmin. Macro moves 0.7551 → 0.7539. The criterion works; the cap is an empirical choice.
Are the DUFS gates better than picking views at random?
Barely, and not significantly: +0.31pp, 15W/10L, p=0.300 against a random subset of the same size. The λ-tuned variant is +0.05pp (p=0.634). What pays is the size reduction, worth +0.50pp over full-pool L-SML. Both things are true at once: the selection is stable, structured and reproducible — six views on every cell — and the AUROC is largely insensitive to which ~17 of 30 you take. That is a statement about pool redundancy, and the grouping analysis says the same.
If nothing you built beats the hand-picked subset, what is the contribution?
Two things. First, GOOD_6 cannot say about itself that it was chosen without an answer key; both label-free arms reach the same bar with one bit of prior, and neither gap is significant. Second, and more useful: we measured why nothing wins. Selection contributes 0.06–0.31pp in either arm, weighting 0.09pp, and orientation 1.46pp. The bottleneck is not which views you pick.
Your fusion loses to the single best view on the larger pools. Why fuse at all?
The best single view is label-selected — an oracle and a ceiling, not something a deployed method can reach. It is 0.7593 at full pool against L-SML's 0.7457. The honest reading is that it bounds the headroom, and it is exactly what the selection line is trying to approach. Note also that full pool with oracle K scores 0.7573 — essentially tied with GOOD_6 — so a good chunk of that headroom is a K-selection problem rather than a selection problem.
How do I know these numbers are current?
Every in-scope script must reproduce the GOOD_6 macro at 0.7594 ± 0.002 before it may report anything (inscope_bench_common.assert_good6); if it does not, the loaded data is not the data the committed numbers came from and the run is void. The scoreboard page additionally re-derives both arms per cell and aborts the build on any drift above 5e-4 from the recorded values. AUROC is always raw, never max(a, 1−a), and UnlabeledCell has no labels field, so label leakage into selection is structurally impossible.
