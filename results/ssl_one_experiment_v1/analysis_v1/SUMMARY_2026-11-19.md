## 1. The question

The advisors asked for two things without gold labels:

1. a **self-supervised calibration** of the step score, and
2. an **answer-level gate**: decide per answer whether to mark steps at all (GAP marks at least one step in every
   answer, so ProcessBench F1 is 0 without a gate).

The idea: inject errors at a known place into real answers. Those answers are free "known wrong" examples. They can
fit the readout (stages S/S2/A) and set the gate threshold through the estimated share of wrong answers, pi-hat
(stage G, BBE positive-unlabelled estimate). This only works if the injected errors look like real errors to the
model. That is checked first (C2ST realism stop rule: classifier AUROC <= .65 and correlation-pattern agreement >= .5).

## 2. The gate classifier (as in `run_analysis.py`, `ssl_stages.AnswerModel`)

| Part | What it is |
|---|---|
| Input | the 16 telemetry channels per step (entropy, chosen surprisal, margin, energy, turnover, JS, BOCPD, realized_z/drv, digit channels ...), after the step readout (top10 by default) |
| Label-free preparation | per-channel sign from the correlation with the fused step score; pool ECDF per channel; sort the steps inside each answer; soft top-M per channel (M = 1: the most unusual step) |
| 17 answer features | 16 channel features + one Simes feature (combined p-value over the steps of a step score s_g) |
| Fusion | z per feature, answer-level L-SML (label-free linear weights) -> answer score sA |
| Calibration (the SSL part) | pi-hat by BBE: scores of the synthetic wrong answers vs the unlabelled pool, 2-fold cross-fit by question group; open the pi-hat share of answers with the highest sA; mark steps only in open answers |

What gets calibrated where:

| Stage | Learns | Level | Ran |
|---|---|---|---|
| S | soft top-N tokens per channel in the step readout | step | yes (V3+V4 mixture, PRMBench dev) |
| S2 | S plus a clean-step proxy | step | yes, not kept |
| A | soft top-M steps per channel in the answer features | answer | no (stop rule) |
| G | the gate threshold pi-hat | answer | yes, as dev checks (sections 6-9) |

## 7. First error vs later errors (dev, PRMBench; `ONSET_DIAG/`, commit cd4f29e)

- 68% of wrong PRMBench answers have more than one labelled error (3,026 first, 3,522 later).
- First vs later: AUROC .811 on the 16 channels, .779 matched on position (position alone .69 in the
  first-earlier direction). First vs clean steps before it .871; later vs clean steps after the first error only .654.
- Signal (per-answer z means): the first error is a jump on all channels (chosen surprisal .95, realized_drv 1.03,
  realized_z .73, BOCPD .75); later errors keep a raised level (entropy .47) without a jump (realized_z -.25).
- Stop-rule C2ST vs **first errors only** (PRMBench): V2 .772, V3 .743, **V4 .642 pass**, V5 .745, V3+V4 .686.
  V4 is the only first-error-like fake; V3's jump is about a third of a real one.

## 8. The answer-level gate on dev (`GATE_DEV/` a04fc0c, `PARENT_SPLIT/` 35d8264 + 810af19)

ProcessBench (1,695 answers, pi .646, answer score AUROC .82):

| Known-wrong set | pi-hat | Wrong opened | Clean closed | F1 |
|---|---|---|---|---|
| no gate | - | 100% | 0% | 0.0 |
| V3 / V4 / V3+V4 | .889 / .526 / .813 | 97 / 71 / 93% | 26 / 80 / 39% | 30.9 / 40.2 / 37.7 |
| V4, clean parents only (label-selected, diagnostic) | .661 | 83% | 65% | 41.9 |
| true pi, same ranking | .646 | 82% | 66% | 41.7 |
| label-perfect gate | - | 100% | 100% | 54.8 |

- PRMBench: every gate lowers PRMScore (true-pi gate 67.76 vs 68.33 without gate); the answer score (.676) is too
  weak to close the 13.5% clean answers. **The gate question is a ProcessBench question.**
- Parent split: V3 on wrong parents gives PB pi-hat .651 (true .646), on clean parents .984; V4 on clean parents
  .661, on wrong parents .417. Real wrong answers of the other fold as positives ("perfect synthetic") give .686 PB
  and .904 PRMBench: BBE itself overestimates a little.
- With the right threshold the PB gate reaches 41.7 F1; the gap to 54.8 is ranking quality, not the threshold.
- Caveat: choosing "clean parents" uses labels. A label-free proxy is still needed.

## 9. Error-direction ideas (Omri, 2026-11-19; `DIRECTION_QUICK/`, `REACTION_DS/` 1e966d1)

- Mean difference (synthetic minus own parent, 17 z-scored answer features), cross-fit: PRMBench answer AUROC
  .676 -> .73 (V4 .732, V3+V4 .725), about a third of the way to a supervised LR (.822). PB unchanged (.81-.82 vs
  .865 supervised). The direction is stable (cosine .998 between halves). Its BBE pi-hat is still off.
- One direction per error type + SML: the directions are nearly the same (cosine .76-.97) and the per-type scores are
  correlated .96-.98 given the label, so SML = equal average (PB .813, PRMBench .727). Error types differ in shift
  size, not direction.
- Per-answer reaction sA(variant) - sA(original) per type, then Dawid-Skene / Gaussian latent class: reactions are
  larger for clean answers (PB V1 median 3.30 clean vs 1.45 wrong), AUROC .73-.79 PB, .63-.74 PRMBench, but mostly
  explained by the original's score (inside sA strata .54-.58 PB, .56-.71 PRMBench); conditional Spearman between
  types .50 PB, .56 PRMBench. pi-hat is not identified: binary DS follows the vote cut (PB .35/.47/.61 for cuts
  q35/q50/q65); Gaussian latent class .52 PB, .56 PRMBench vs .646 / .865. Gates at these values: PB F1 29-41 (true
  pi 41.7); PRMBench 57.8-63.2 (no gate 68.3).

## 10. What we learned

1. Injected errors are detectable mainly by how loud they are. Too loud (V1, V2, V5) fails; one changed number (V3)
   is too quiet at the step; a same-question step (V4) is closest to a real first error.
2. The answer-level gate is worth pursuing on ProcessBench only. Its threshold can be right (V4 clean parents, V3
   wrong parents), but which synthetic set gives the right threshold depends on the original answer's label, which we
   do not have.
3. Within-answer: the first error is a jump; later errors are a raised level. A start-of-error target and a
   general-error target need different channels.
4. Different error types do not give independent views; the shared "more uncertainty" factor dominates all 17 answer
   features.
5. A synthetic-pair direction improves the PRMBench answer ranking (.676 -> .73) without labels.

## 11. Open directions (not started; each needs Omri's go)

- Label-free choice of "probably clean" originals (e.g. lowest answer score, majority final answer) for the
  known-wrong set, then the PB gate on dev.
- Known-shift mixture for the threshold: pool score = (1 - pi) f + pi f(x - delta), with delta from one error type
  that is close to a real error (V4) and from "probably clean" parents. Do not use "every error type gives the same
  pi" as a check: the types move a clean answer by different amounts (PB median sA shift of a clean parent:
  V3 .46, V4 2.53), so the pi of each type must differ by construction.
- Separate difference directions on "jump" channels and "level" channels as two views for SML.
- First-error target: only step k positive, later steps ignored; realism vs first errors only.
- The synthetic-pair direction as the PRMBench answer score: check PRMScore and stability, not only AUROC.
- Double injection (a second error into a synthetic answer): a label-free reference for how a wrong answer reacts.
  Needs a GPU pass.
- Learn N (readout) or lambda from about 50 labelled answers (Step 487: 50 PRMBench labels were enough to beat AUTO
  in the supervised-weights check). This is not label-free.
- ProcessBench V2 GPU run (still waiting for Omri's choice).

## 12. Deviations from the pre-registered plan, and limits

- V3, V4 and V5 were added after the realism stop (Omri's choices on 2026-11-18). The pre-registered plan named V1
  and V2 only.
- V4 GPU runs used a report-only numeric prefix tolerance (Omri's written approval); the strict smoke result is kept.
- Gold labels were used for diagnostics only: the parent split, the perfect-synthetic reference, the true-pi gate and
  all AUROC values. No label entered a fit, except the stage-S lambda choice and keep rule, which use dev labels as
  pre-registered.
- The two `DIRECTION_QUICK/` checks (mean difference, per-type SML) ran as quick checks before a formal go; their
  scripts and outputs are kept so that they can be reproduced. `REACTION_DS/` ran after Omri chose it.
- The dev pool was inspected many times. All dev numbers are development evidence. The PRMBench test half was scored
  once (2026-11-18), only with arms that do not depend on any SSL choice.
- PB V4 covers only 25% of the dev answers (421); V4 on clean parents has 149 PB answers.
