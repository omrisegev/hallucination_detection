Why the current code uses top ten

First, the current token head combines the P telemetry views into one risk value per token. 1. An alternative pooled design: learn from differences within an answer

Scope clarification: this section describes pooling centered steps from many answers. It is different from Omri's clarified request for a separate fit inside each answer. Correcting the existing diagnostic remains useful for interpreting v2, but does not implement that request.

Question: are the new step weights learning which answers are generally risky, or which step differs from the other steps in its own answer?

The simplest diagnostic separates pooled covariance into within-answer variation and between-answer variation. Then inspect how much of the dominant direction comes from each. This uses the new step matrix directly. It does not require a graph or fitting a model separately on every short answer.

A concrete implementation mismatch: the v2 protocol promises a within-answer-centered covariance weight-profile diagnostic. In run_v2.py:332–334, the implementation instead subtracts the global column mean of all training steps and adds a scalar grand mean. It never groups by answer for this calculation. Since SML computes np.cov, subtracting a constant per column does not remove between-answer covariance. The current centered_profile cannot establish the promised comparison.

This is a source-level finding, independently checked without reading outcomes. It affects interpretation of the diagnostic; it does not show that the primary raw-step scores are wrong. Correct the diagnostic in a disclosed additive pass before using it to decide whether within-answer structure matters. Preserve its old artifact and leave the live scoring code untouched.

If that diagnostic supports the hypothesis, discuss one new scored arm: fit the existing fuser on donor step vectors centered within each answer, keeping the response detector fixed. Separate changing how weights are learned from changing the held-answer scoring rule. This is distinct from Step 293's CIW-based token residualization. Use the pooled comparison as control; centering may also remove useful evidence, especially for every-step PRMB ranking.

Fitting a separate p×N matrix inside every answer is another possible direction, but short answers may provide fewer independent steps than views. A pooled within-answer covariance is the smaller first step. A per-answer model would need an explicit stability and fallback rule, not an assumed benefit from being more local.

2. Complementary investigation: calibrate the opportunity to produce a risk peak

Question: is a step suspicious compared with other steps of similar length, or does it simply contain more opportunities for a high token score?

A long step can have a large maximum or top-ten mean just because it contains more tokens. A new line, an equation or a step-opening phrase can also change the token distribution without introducing an error. The HMM report explicitly left one important control unresolved: compare the peak at an error boundary with peaks at matched correct boundaries.

First inspect that confound on older, already-opened examples. Match correct and first-error steps by length, relative location and boundary position. Use token roles such as numbers and operators as explanatory diagnostics. Do not immediately hard-mask them or assume their uncertainty is irrelevant.

If length explains a meaningful part of the mistakes, the candidate is a length-conditioned reference percentile: keep the existing token head and reducer, then ask how unusual its step score is among donor steps of similar length. Use actual donor sequences so token dependence is retained. This changes comparisons between steps, not the covariance solver. Keep the response detector fixed in the first comparison so any benefit can be attributed to choosing the error location.

Why this is distinct: top-k versus mean, length-proportional tails, early-score length residualization and Module-B order-statistic weighting have already been explored or registered. Calibrating the distribution of a fixed step-tail statistic conditional on its opportunity count is a narrower, different test.

Cost and limits: existing caches and CPU should be enough. Fitting can use unlabeled donor steps, but the resulting percentile is relative to a mixture of correct and incorrect steps; it is not a clean-null p-value or a probability of correctness. Length conditioning is an explicit modeling assumption. Correct-only calibration uses labels. Hard-coded token-role rules would introduce hand-picked prior knowledge. Stop if the matched controls do not support the confound, or if calibration removes real error evidence.

The missing control is stated in the HMM report. The audit memo distinguishes it from earlier length and reducer experiments.

3. Conditional revisit: a sequence model over the new steps

Yes, an older temporal idea can be worth revisiting here. An HMM over token risk, a covariance model over independent answer summaries, and an onset rule over learned step scores operate on different observations. In the last case, a transition corresponds to a reasoning step rather than a punctuation or token boundary.

Use the step scores from one frozen Module-B pipeline in chronological step order. First check whether errors tend to produce a sustained change and whether wrong locations are mainly selected too late. Only then choose one sequence rule to compare with the same pipeline's existing locator. Sorting token risks inside each step loses token order; it does not prevent preserving the order of the steps themselves.

For a claim that the new representation enables the temporal method, use a small matched comparison: old versus new representation, each with and without the same temporal mechanism, on the same questions and metric. Report the change in its incremental benefit. A win under the new representation would support that adaptation; a repeated negative would close this precise version more convincingly. Do not turn this into another HMM/BOCPD/Kalman sweep.

A simple unsupervised sequence rule can preserve label-free fitting, although persistence assumptions are explicit. A directly first-error-trained model adds supervision and belongs to the optional route below. The existing absorbing-HMM failure is a reason to test the persistence assumption, not to assume all later steps remain erroneous.

4. Larger alternative: measure whether the step is valid

Question: does the current statement follow from the problem and the preceding valid steps? Entropy measures uncertainty about wording. A fluent arithmetic mistake can have low uncertainty, while a correct unusual calculation can have high uncertainty. This is a possible explanation to investigate, not a finding established for every failure.

Start with one narrow, checkable relation. For example, a candidate arithmetic checker can verify an explicit equality and return “unknown” when parsing or mathematical assumptions are ambiguous. A model-based alternative holds the candidate step fixed and compares its score under a relevant premise change and a matched benign change. The latter measures sensitivity; sensitivity alone does not establish validity.

The necessary control is whether the measurement distinguishes invalid steps from equally unusual valid ones, including natural errors rather than only synthetic corruptions. Check whether it catches errors missed by IU/H3 before deciding how to combine it with them. Report coverage and the cost per checked step.

Why this is distinct: C8 self-innovation, EDIS, Evidence-Drop and RAG evidence perturbations are already part of the project history. “Context-dependent surprise” is not new by itself. The specific opening is a controlled mathematical step-validity measurement. Earlier A6/PTNI proposals also considered typed interventions; this is not permission to restart that withdrawn line.

Cost and limits: arithmetic checking introduces explicit domain knowledge and has limited coverage. Model contrasts require extra inference. A trained PRM adds supervision and a different access/cost tier. These can be useful localization approaches, but they do not preserve every assumption of the original label-free, no-hand-picked-prior method.

Do not use “a continuation reaches the right final answer” as the definition of a valid step. A model can recover from a bad step or fail after a good one. The PRM literature documents this difference between step verification and predicting eventual success. The Lessons of Developing Process Reward Models.

5. Optional diagnostic: train directly for first error or no error

Question: is useful information present in the existing features, but poorly matched to the current training objective?

A small supervised sequence readout could assign probabilities to “first error at step 1, 2, …” and “no error.” Its loss would use the known first-error event; all-correct traces supply no-event observations. Steps after the first error must not be silently labeled correct. Use question-grouped training and evaluation, accounting for the same questions scored by different models.

Why this is distinct: the old HMM learned sequence likelihood without correctness labels; the earlier cumulative hazard was a predefined accumulator. Module B already has supervised independent-step LR and already excludes post-error PB steps. The new part would have to be the joint first-error/no-error objective, not merely using labels, censoring later steps, or renaming a hazard.

My priority: wait for Module B's supervised reference before considering this. It is a diagnostic or a separate supervised research branch, not the primary label-free contribution and not a mathematical upper bound. Failure of one small model would not prove the features contain no useful information.

The benchmark target is explicitly first error or all steps correct: ProcessBench. The proposed training objective is our possible adaptation, not a result claimed by that paper.

06 · IMPORTANT GAPS

What deserves attention before another model variant.

Some of these issues were noticed earlier and then buried in the log. Others are concrete findings from this review. They should not all be described as discoveries that nobody had considered.

Verified now

1. The safety checks need their own end-to-end test

A claimed green pre-label audit did not catch the manifest collision or enforce label opening. Test the actual path from a completed fold to a rejected/accepted evaluator launch, including missing and changed files. Unit identities alone cannot certify that path.

Underused result

2. Family balancing may be the useful prior

Equal-family is almost B3 on the global panel. Family-NRM also admits a provenance prior. State what the method knows: an orientation bit, feature families, score semantics, calibration labels. “Label-free” does not mean “without assumptions.”

Repeated finding

3. The readout can matter more than the solver

Joint v1 preserved very similar detector rankings but sharply reduced activation. The CIW cross-scale study traded PB F1 against PRMB ranking through answer-level scale. Separate feature quality, fusion, token-to-step reduction, and threshold calibration in the analysis.

Unfinished confirmation

4. A new model is not a new question

Qwen and Llama scoring the same ProcessBench traces share the same problems and annotations. They test scorer transfer. Repeated study of those questions consumes their value as untouched evaluation, even when each new fit hides the labels.

Interpretation risk

5. ProcessBench F1 mixes two capabilities

It is the harmonic mean of clean-trace accuracy and exact first-error accuracy. A gain can come from abstention rather than a better locator. Always show both components, the activation rate, and localization on erroneous traces.

Hypothesis to bound

6. Tail fusion is not temporal reasoning

Order-statistic fusion is sensible because slots align across steps, but it loses order. The v2 grid tests how much to trust large token risks. Avoid claiming temporal dynamics unless order-sensitive evidence supports that separate claim.

Reporting debt

7. Composition can create a strong pooled score

CIW RAGTruth's pooled AUROC is 0.7712 while its QA/Data2txt macro is 0.6302. Report within-task discrimination, class prevalence, and source-group uncertainty before calling this a broad grounding gain. The contrast is a warning about composition, not proof of a specific confound.

Deployment gap

8. “Single pass” needs a cost definition

Generation-time telemetry can be nearly free after one generation; scoring a supplied PB trace still requires teacher forcing. White-box hooks and RAG context interventions have other costs. Report scoring latency, fit time, peak memory, stored bytes, and number of model passes.

A legacy evaluation helper still deserves quarantine

scripts/logistic_oracle.py:77–115 applies max(AUC, 1 − AUC) inside test folds and bootstrap draws. That chooses the better orientation from evaluation labels. For example, an observed AUC of 0.40 becomes 0.60. It is appropriate only as an explicitly labeled sign-oracle diagnostic, not ordinary held-out discrimination.

The same legacy function bootstraps rows within folds even though its split API can group questions. If several rows share a source question, that uncertainty calculation does not preserve the dependence. It also substitutes 0.5 for undefined/single-class cases.

Action: mark this path historical, trace which manuscript tables depend on it, and recompute only those tables with fixed orientation, grouped uncertainty, and undefined-case reporting. This is not evidence that the newer certified pipelines use the same helper.

Legacy helper · Report that reads its pickle · Guidance that currently recommends it

Three mathematical statements in the documentation need correction
  • Z-scoring gives Pearson correlation from covariance, not Spearman correlation. Rank-transforming first is a different operation.
  • Low pairwise Spearman correlation is not conditional independence given correctness. A correlation cutoff cannot certify the L-SML assumptions.
  • Supervised LR is not a guaranteed upper bound. It optimizes a surrogate loss with finite data and regularization; a label-free method can beat a particular held-out LR fit. Class balancing is the project's chosen comparator convention, not a theorem guaranteeing higher AUROC.

Keep the actual empirical corrections. Remove the overstated general claims from current guidance. An in-sample optimized reference is an optimistic diagnostic, not a validated generalization ceiling.

Normalization discussion · Early independence wording · LR guidance

One further labeling check: an incorrect final answer, a first invalid reasoning step, and a claim unsupported by retrieved evidence are different targets. Use “hallucination” as the project umbrella, but name the actual target in each experiment. A correct answer can contain a bad step; an incorrect answer can be confidently generated.

A small glossary for this review.

TermPlain meaning here
CellOne dataset/model/temperature or scoring-protocol combination. Different cells can reuse the same underlying questions.
H(n), ΔE(n), ZnToken entropy, the project's sampled-token negative log probability (“spilled” stream), and a raw-logit partition/energy stream. They are distinct saved quantities; the exact schema defines the convention.
View / feature / familyA numeric measurement, such as entropy variation; a family groups related measurements by source or operator. Hand-assigned family membership is a prior.
L-SML, IU-PCR, DUFS-LIUDifferent ways to combine features using their statistical structure. L-SML models groups; IU-PCR is the independent-deviation U-PCR arm; DUFS-LIU adds a graph/gating-related correction. Version and config matter.
B3 / CIW-DEEMThe project's continuous DEEM-derived fusion line and its cross-fitted innovation-weighted input challenger. “Official challenger” does not mean it passed its promotion gate.
Reducer / readoutThe rule that turns many token risks into one step, span, or answer risk. Examples: maximum, top-ten mean, or learned weights on sorted risks.
Label-free scoringThe score estimator does not fit to correctness labels. Feature development, model selection, sign priors, and threshold calibration may still use information that must be disclosed.
Macro / paired intervalMacro gives equal weight to the stated cells or families. A paired interval uses the same resampled source groups for both methods. An interval containing zero means the comparison is inconclusive, not proven equivalent.
Retrospective / scorer transfer / confirmationAlready-examined populations; a new scoring model on existing examples; and an evaluation whose new examples and labels were not used to develop the tested method. These support different claims.
