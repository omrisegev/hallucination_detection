1 The problem: many clues, one score

For each token or window, we calculate several features. Each feature is a clue about the answer. We want to combine those clues into one useful score.

Imagine three students reviewing the same solution. They all say, “This step looks suspicious.” That sounds like strong evidence. But if all three copied the same mistaken note, their agreement is less informative than three independent judgments.

Features can have the same problem. Several features derived from the same entropy trace may rise together, even when they are not providing three separate pieces of evidence.

Feature score

A number such as an entropy statistic for this observation. A high number is not automatically a high probability of error.

Weight

How much a feature contributes to the final sum. Weights can differ and can be signed. They are not necessarily probabilities that add to one.

Dependence

Two features tend to move together. We measure this pattern over many observations, using covariance.

One fused score = w₁ × feature₁ + w₂ × feature₂ + … + wₚ × featureₚ

Equal averaging fixes all weights in advance. Our methods try to learn useful weights from the relationships between features. In this project, the estimator learns those relationships without correctness labels. We still need labels later to measure localization performance; the tuned v2 comparison also uses training labels to choose configurations.

Where does ordinary SML fit in?

SML — Spectral Meta-Learner — learns a weighted combination from how its input scores co-vary. In its motivating model, agreement across otherwise independent predictors can reveal a shared signal. The “spectral” calculation uses an eigenvector; you do not need that calculation to follow the distinction below.

If several inputs share an extra source of dependence, the pattern of agreement can be misleading. That motivates organizing dependent inputs into groups. Our continuous implementation adapts the idea to feature scores; it does not inherit every guarantee of the original binary-classifier setting.

2 L-SML: combine within groups, then combine groups

L-SML gives related features an intermediate group score before combining the groups.

For illustration, suppose nine features form three groups. Think of them as three study groups: each group first prepares one report, then the reports are combined. The current INTERNAL comparison learns the groups from data; their colors below do not represent a manually chosen feature list.

Conceptual flow, not fitted weights. In v2, an SML stage with exactly three inputs uses the registered equal-weight guard after standardization. The diagram shows the architecture; the guard limits which weights are actually learned.

  1. Find groups of dependent features. In the current comparison, both internal_cont and internal_joint use the same INTERNAL group-discovery recipe.
  2. Learn a combination inside each group. L-SML uses only that group's inputs at this stage.
  3. Create one score per group for each observation. A “virtual classifier” is just this intermediate score; no new language model is trained.
  4. Learn how to combine the group scores. The second stage sees the summaries produced by the first stage.
The key property is staged learning. First produce the group summaries; then combine them. The cross-group stage does not go back and jointly revise all the within-group weights.

What is the limitation? When learning inside Group A, strong agreement may reflect a broad signal shared with B and C, or something specific to A. The local stage does not explicitly separate these two sources. A later combination of the group summaries cannot necessarily undo that earlier mixing.

3 Joint: explain both sources of agreement together

Joint adds an explicit model of why features move together. It estimates the shared part and the group-specific parts in one coupled fit.

Return to the study-group example. Instead of accepting each group's report first, we examine all reviewers together and ask two questions: “What tendency is shared across all groups?” and “What extra tendency is shared only within each group?”

Across different groups

Under the model, features in different groups share the global factor. Their covariance helps constrain that common component.

different-group agreement ≈ shared part

Inside the same group

Features can share the global factor and an extra group factor. Their covariance helps estimate the additional dependence.

same-group agreement ≈ shared part + group part

A small numerical example

Suppose the features have been standardized. We construct this simple example:

“Together” describes the objective, not a simultaneous computer instruction. The code repeatedly updates the shared loadings and group loadings to reduce the same covariance-reconstruction error. It tries several initializations. In these variants, group membership is determined first; “Joint” does not mean groups and loadings are learned in one end-to-end optimization.

The common factor is not automatically correctness. It is a statistical explanation of agreement. It might also capture difficulty or some other shared variation. Joint can explain covariance more accurately and still produce worse localization scores.

QuestionL-SML referenceJoint L-SML reference

Is it guaranteed to locate errors better?No.No. A richer model creates a testable hypothesis, not a guarantee.

There are really two decisions: fit a model, then turn that model into weights.

Our original internal_joint reference still uses a hierarchical scoring rule. It forms each group score from the fitted shared loadings v, then combines those scores. The group loadings u helped estimate v, but they are not used directly in that final scoring formula.

This explains why our newer variants are more than cosmetic changes. Some change the model fit. Others change the way the fitted model is used to calculate the final weights.

What “Joint” improves in principle: it can separate sources of dependence that staged within-group learning mixes together. What still needs to work: the fitted shared structure must be useful for error localization, and the weight rule must preserve that useful information.

5 Now our improvements have a clear purpose

A graph is a set of nodes and weighted connections. In our methods, it records structural similarity. The nodes might be features or observations; the later diagrams show which. A connection does not tell us that an observation is correct.

Change the fit

Joint + gates

Question: should some feature coordinates have more influence before we fit Joint?

DUFS learns a soft importance value for each feature using graph-based structure. We rescale the feature columns, refit Joint, and recompute its hierarchical head.

Analogy: change how strongly each reviewer's observations enter the analysis. The fit is redone; we do not just multiply the old answer by a gate.

Change the weight rule

Joint + diagonal

Question: can we use the full fitted covariance, including the group factors, while discouraging large coefficients on weakly gated features?

We solve for weights from the Joint model covariance and add a separate penalty for each feature coefficient.

Analogy: avoid giving a reviewer a large final influence if the gate learner gives that reviewer little structural support. This support is not measured accuracy.

Change the weight rule

Joint + LIU

Question: can we use the full fitted covariance and avoid unnecessarily rough scores across similar observations?

We add a graph-based penalty when solving for the weights. It discourages disagreement of degree-normalized scores across similarity edges.

Analogy: similar feature patterns should not receive sharply inconsistent assessments without support from the rest of the objective. This may help, or it may blur an error boundary.

Before crediting the penalty, check the new weight rule alone. Both diagonal and LIU switch from the hierarchical head to a model-inverse head. Their λ=0 reference makes that same switch without the added penalty. Otherwise we could mistakenly call a better weight rule a “graph improvement.”

The implementation minimizes the off-diagonal residual with multiple deterministic starts. It then builds Cmodel from the fitted shared and group terms plus nonnegative residual diagonal variance.

Model fit and localization are different objectives. A shared covariance factor can reflect answer difficulty, scale or other variation. A better covariance fit does not automatically identify the first wrong step. That is why the way we derive w needs its own test.

C “The graph” can mean three different things

The nodes are not always the same objects. Keeping them separate explains what each variant actually changes.

A · feature grouping

Nodes = P features

Remove an initial rank-one covariance estimate, then use the absolute residual as affinity. Spectral clustering and leave-one-answer-out consensus choose stable feature groups.

Used by all selected INTERNAL variants. Their base grouping is ungated. The separately tested internal_gaff_* family changes this grouping graph; it is outside your selected scope.

B · learning DUFS gates

Nodes = sampled observations

DUFS repeatedly changes feature gates, rebuilds a self-tuning observation affinity, and uses a diffusion objective to learn which features support that structure.

Current code: dense batch affinity with a k=7 bandwidth rule; two diffusion steps; 120 epochs; three seeds. Mean survival probabilities are RMS-normalized into q. These are structural gates, not calibrated correctness probabilities.

C · LIU score regularization

Nodes = fit observations

LIU builds a sparse k-nearest-neighbor graph using distances in gated feature coordinates. Its normalized Laplacian becomes a penalty in the final weight calculation.

Edges mean feature similarity, not “next token” or “next step.” Only liu adds this graph in the final solve. The graph can connect different answers in the current pooled fit.

Joint fits shared and group loadings together. Its hierarchical head forms one virtual score per group using v, then fuses those group scores with SML.

t_g = Z_g v_g; s = Σ_g a_g t_g
What it hopes to gain

Model extra within-group dependence while estimating the shared factor.

What could go wrong

Better fitted covariance may not give a better score. The hierarchical head does not directly use u; u affects the joint fit of v indirectly.

Reference: compare with internal_cont on matching groups. This isolates the Joint fit plus its weight rule.

The two references: what changes between CONT and Joint?

internal_cont: after INTERNAL grouping, fit a continuous L-SML combination inside each group; form group scores; combine those scores in a cross-group SML stage. It does not jointly fit the shared v and group u model.

internal_joint: estimate v and u together from covariance. Within each group, build a score with that group's entries of v. Then use cross-group SML. The fitted u terms influence estimation, but are not inserted directly into the final hierarchical weight formula.

Small-group guard: v2 enables an equal-weight-over-standardized-inputs guard for SML stages with exactly three units. When INTERNAL selects K=3, the hierarchical cross-group stage is guarded. Do not interpret every difference as an unrestricted learned cross-group weighting.

Joint + gates: change the coordinate system before fitting

Start with the same ungated INTERNAL groups. Learn q using DUFS. Set qλ = (1−λ)1 + λq, and scale each feature column by its effective gate. Joint is fitted again in these gated coordinates. The hierarchical head also operates there.

Q = diag(qλ)
Z′ = Z Q; C′ = Q C Q
Fit Joint + hierarchical head on Z′ → w′
Return w = Q w′, so Z w = Z′ w′

gate050 uses λ=0.5; gate100 uses λ=1. These values interpolate between no gating and the learned gates. This is more than multiplying the old final weights by q. The fit and head are recomputed. The selected variant does not rebuild the INTERNAL groups with gates.

Joint + LIU: use the fitted covariance, then penalize graph roughness

Reuse the ungated Joint fit, including v and u through Cmodel. Build a kNN sample graph using gated distances. Let L be its symmetric normalized Laplacian. Convert that sample graph into a P × P penalty:

R = Zᵀ L Z / N
R̄ = R · trace(Cmodel) / trace(R)
A = Cmodel + λR̄
w = solve(Ψ(A) + γI, v)

liu010 uses λ=0.1; liu050 uses λ=0.5. The trace match puts the penalty on a comparable total scale. The code uses zero roughness contribution when its trace is negligible.

For s=Zw, the roughness is sᵀLs/N. With this normalized L, it penalizes differences between degree-normalized scores across similarity edges. It does not directly force consecutive reasoning steps to have the same score.

Possible benefit: discourage weights that make structurally similar observations disagree sharply. Risk: if the graph connects correct and incorrect regions, it can suppress a useful local error signal.

Joint + diagonal: use graph-informed gates as a per-feature penalty

Reuse exactly the same ungated Joint model as LIU. Instead of adding the sample-graph roughness matrix, penalize feature coefficients separately according to q.

Dq = diag(1 / max(qj, 10⁻⁶)²)
D̄q = Dq · trace(Cmodel) / trace(Dq)
A = Cmodel + λD̄q
w = solve(Ψ(A) + γI, v)

diag010 uses λ=0.1; diag050 uses λ=0.5. A smaller gate gives a larger relative coefficient penalty. This is soft regularization, not a hard rule that deletes the feature.

“Graph-free” needs a qualifier: there is no extra sample graph in this final solve. INTERNAL grouping and the DUFS gate learner still use graph-based structure. The method is not entirely free of graphs, and its full runtime still includes gate learning.

Numerical detail: what do Ψ and γ mean?

The implementation first adds the selected penalty to Cmodel. It then projects the complete system A to positive semidefinite form, Ψ(A), and adds an analytic ridge γI. The target condition number here is 10³. Thus the exact implementation projects the sum, not just the covariance before adding a penalty.

The raw inverse-map vector then passes the same donor-score SD=1 and orientation boundary as the other v2 arms. A larger λ changes the pre-normalization solve; it is not a promised monotonic change in every final coefficient or localization metric.

G What this means for our one-answer window study

Our primary goal is to learn the localizer from the current answer alone whenever its trace supports a stable fit.

The boundary applies to both fusion axes.

Normalization, feature groups, gates, covariance, feature weights and any learned trajectory reducer must be fitted from this answer. Width and regularization use declared fixed rules or this answer's unlabeled diagnostics. Borrowed groups, fitted parameters or a correctness threshold calibrated on other answers belong to a separate hybrid comparison. Pooled fitting is a secondary comparison or disclosed fallback.

For the planned N-window × P-feature matrix, feature fusion produces a local risk curve. The trajectory stage must preserve the information needed to locate the first erroneous official step. Its exact units and fitting observations still need to be defined and tested. A longer trace gives more fitting observations; it does not guarantee useful variation or identifiable errors. An answer-only rule for the “no error” outcome remains part of the required work.

What we can carry forward

  • The shared-plus-group covariance model.
  • The distinction between fitting Joint and deriving its weights.
  • The six selected extensions, two references, and λ=0 inverse reference.
  • A matched IU baseline and simple averages to measure whether extra complexity helps.
  • The same window features for the primary one-answer fit and secondary pooled comparison.

What cannot be copied unchanged

  • Leave-one-answer-out grouping: the current implementation requires at least three answer owners. The strict one-answer fit needs its own stability rule, such as blocked window resampling. Groups learned from other answers are a separate hybrid arm.
  • Sample graph k=7: with eight fit windows this connects each window to every other one. That is a very different graph from the current token graph.
  • 23 token streams → 30 window definitions: feature validity, constant columns and group eligibility change.
  • Overlapping windows: extra rows share information. Treating them as independent evidence would overstate support.

The eight-window issue is concrete: our 400-answer GSM8K feature audit found a median of eight nonoverlapping fit windows at width 32. This was a feasibility result, not an approved fitting threshold or an optimal window size.

None of these fusers alone chooses the first wrong step or the “all correct” outcome. They provide scores. The window-to-step mapping and no-error decision must be specified separately and kept comparable. Using the full answer is an offline localizer, not a demonstrated causal early-warning system.

My interpretation, not a measured ranking:

Joint + diagonal is a useful first model-inverse candidate because it uses the fitted group structure with a simpler final penalty. LIU is its direct graph-based comparator. The gate family asks a different question: should graph-informed geometry change the Joint fit itself? Keep both references so these explanations do not get mixed together.
